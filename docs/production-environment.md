# Production environment contract

This is the canonical reference for the existing ECS target. Values are supplied
at deployment time and are intentionally omitted. Do not copy development
credentials or `.env` files into production. ECS receives runtime credentials
from Secrets Manager; Terraform variables contain deployment metadata, not
application passwords.

## Runtime settings

| Name | Requirement | Consumers / purpose |
| --- | --- | --- |
| `APP_ENV` | Required; `production` | API and worker security behavior. |
| `ALLOWED_ORIGINS` | Required; HTTPS origin for the owned domain | Credentialed browser API requests. No wildcard. |
| `ALLOWED_HOSTS` | Required; owned hostname | Host-header allowlist. No wildcard. |
| `TRUSTED_PROXY_CIDRS` | Required for the ALB path; VPC CIDR | Trust forwarded client addresses only from the ALB/task network boundary. |
| `ENABLE_HSTS` | Required; `true` behind HTTPS | Enables production HSTS; the Nginx HTTPS edge also emits HSTS. |
| `LOG_FORMAT` | Recommended; `json` | Structured container logs. |
| `DB_SSL_CA_FILE` | Required by the AWS profile; `/app/app/db/rds-ca-bundle.pem` | Verified RDS TLS. The path refers to the committed public AWS CA bundle. |
| `LLM_PROVIDER` | Required; `fake` by default | `fake` avoids external calls; set `openai` only with an approved credential. |
| `LLM_MODEL` | Optional; code default `gpt-4o-mini` | Model identifier used only by `OpenAIProvider`. |
| `ACCESS_TOKEN_EXPIRE_MINUTES` | Optional; default `10` | Access-token lifetime; valid range 1–60. |
| `REFRESH_TOKEN_EXPIRE_DAYS` | Optional; default `7` | Refresh-cookie lifetime; valid range 1–30. |
| `LLM_TIMEOUT_SECONDS` | Optional; default `30` | OpenAI request timeout; valid range 1–120 seconds. |

`WEBHOOK_ALLOWED_LOOPBACK_ORIGINS` is development/test-only and must be unset in
production. `WEBHOOK_ENCRYPTION_KEY` is a secret, not a plain setting.

## Secrets Manager values

The current ECS task definitions read JSON keys from the `${name}/runtime`
Secrets Manager secret. The API, worker, publisher, migration and bootstrap task
definitions receive only the keys they need.

| Name | Required | Purpose / scope |
| --- | --- | --- |
| `DATABASE_URL` | Yes | Verified-TLS PostgreSQL URL for the restricted `emergency_app` runtime role; API, worker and publisher. |
| `REDIS_URL` | Yes | TLS/auth Valkey URL; API, worker and publisher. |
| `CELERY_BROKER_URL` | Yes | TLS/auth Celery broker URL. |
| `CELERY_RESULT_BACKEND` | Yes for API/worker | TLS/auth result backend; PostgreSQL remains the durable job source of truth. |
| `JWT_SECRET` | Yes for API | Random signing key of at least 32 bytes. |
| `WEBHOOK_ENCRYPTION_KEY` | Yes for API/worker | Fernet key used to decrypt signing secrets for outbound delivery. Preserve it when rotating other settings. |
| `METRICS_TOKEN` | Yes for API | Random bearer credential; metrics remain private and are not routed by the frontend edge. |
| `OPENAI_API_KEY` | Only when `LLM_PROVIDER=openai` | Optional provider credential; never needed by the default fake provider. The current initializer writes an empty value. |
| `MIGRATION_DATABASE_URL` | One-off migration/bootstrap only | Verified-TLS URL for `emergency_migrator`; it must not be injected into API, worker or publisher tasks. |

RDS master credentials are managed by RDS and exposed only to the privileged
one-off bootstrap task. Normal services never receive them. Redis AUTH is
generated by Terraform and is sensitive Terraform state; protect state with the
approved encrypted, versioned remote backend and restricted IAM.

## GitHub deployment environment

The manual deployment workflow uses GitHub OIDC rather than long-lived AWS keys.
Configure the protected `production` environment with reviewer approval and a
main-branch deployment rule, then define these environment **variables** (they
are resource identifiers, not secret values):

| Variable | Source |
| --- | --- |
| `AWS_REGION` | The selected deployment region. |
| `AWS_DEPLOY_ROLE_ARN` | Terraform `github_deploy_role_arn` output. |
| `AWS_DEPLOYMENT_CONFIG` | JSON metadata from Terraform `deployment_config`; no secret material. |

The operator must also enter `APPROVE_BILLABLE_DEPLOYMENT` in the manual workflow
input after reviewing the plan and approving costs. Do not add static AWS access
keys to repository or environment secrets.

## Terraform and state inputs

The required Terraform inputs are `domain_name`, `certificate_arn`,
`github_repository`, and the initial immutable `image_tag` (`sha-` followed by
40 lowercase hex characters). `region` defaults to `ap-southeast-1`; sizing,
service count, project name, log retention, deletion protection and an optional
existing GitHub OIDC provider ARN are documented in `infra/variables.tf` and
`infra/terraform.tfvars.example`. Supply the existing approved remote-state
bucket/key/region through a private `backend.hcl`; do not commit state, plans,
real `tfvars`, generated deployment JSON or backend configuration.

`domain_name` must be owned and resolve to the ALB. `certificate_arn` must refer
to an already validated ACM certificate in the selected AWS region that covers
that hostname. No domain or certificate is configured in this checkout. The
Terraform output exposes the ALB DNS target so the owner can add the DNS alias
after approved provisioning; the repository does not create an owned name.

## One-time production bootstrap order

1. Obtain explicit cost approval and configure an authorized AWS identity, an
   existing encrypted/versioned state backend, owned hostname, validated ACM
   certificate and exact GitHub repository. Review a real Terraform plan before
   any apply.
2. After approved infrastructure creation, publish scanned immutable AMD64
   `sha-<commit>` images and export the non-secret `deployment_config` output to
   the ignored `aws-deployment.json` file.
3. Run `scripts/aws_init_secrets.py` once. It generates database-role passwords,
   `JWT_SECRET`, Fernet key and metrics token; writes verified-TLS Postgres and
   Valkey URLs through stdin; sets the provider to FakeLLM by default; and never
   prints secret values. It refuses to overwrite an initialized runtime secret.
4. Run the privileged one-off database bootstrap task. It enables PostGIS and
   creates the separate runtime and migrator roles using the RDS-managed master
   credential. Confirm it exits successfully before running Alembic.
5. Run the Alembic migration task using `MIGRATION_DATABASE_URL`; require
   `upgrade head` to exit zero and record exactly one current head.
6. Start/scale API, frontend, Celery worker and publisher services, then verify
   health/readiness, login/refresh cookies, tenant isolation, two-instance
   WebSocket recovery, real worker jobs, outbox/webhook delivery, metrics policy,
   HTTPS/DNS and a backup/restore drill.

**Do not run the demo seed in production.** Application startup never seeds
identities or operational data. Demo account creation is an explicit
development/test-only command. Provisioning and the bootstrap scripts are
currently unverified against a live account.

## Public portfolio demo profile

- Keep `APP_ENV=production`, Redis-backed rate limiting, verified database/cache
  TLS, HSTS, explicit host/origin allowlists and the metrics bearer token.
- Keep FakeLLMProvider unless an owner configures and budgets a real provider.
  Do not place provider credentials in screenshots, logs or frontend settings.
- Use only the fictional Singapore fixtures. Never import real dispatch records,
  responder details, phone numbers or patient information.
- Registration currently creates a new isolated organization and is rate
  limited, but there is no invitation-only or `PUBLIC_REGISTRATION_ENABLED`
  switch. Before an open public demo, choose an explicit registration policy and
  constrain signup at the application/edge layer; do not assume a setting that
  does not exist.
- `/metrics` is bearer-protected and not routed through the public frontend
  proxy. `/docs` and `/openapi.json` are currently public read-only schema pages;
  keep that as a deliberate demo choice or restrict the edge routes before a
  private/customer deployment.
- The demo reset endpoint is role-protected and tenant-scoped, but an ADMIN can
  reset that ADMIN's own workspace. Do not store non-demo data in a public demo.
- Configure/monitor the map tile provider for the target host. Public OSM tiles
  were blocked by the validation environment used for the checked-in screenshots.

The AWS profile has one NAT gateway, one RDS instance and one Valkey node by
default. Material cost drivers include NAT gateway/hour and public IPv4, RDS
compute/storage/backups, Valkey compute/storage, Fargate task duration, ALB,
CloudWatch ingestion/retention, ECR storage and inter-zone/data transfer. No
current dollar estimate is claimed; review regional prices and resource counts
before applying. A zero desired ECS task count does not make the database,
cache, load balancer or NAT free.

## Current blockers and boundary

returns `NoCredentials`. There is no owned domain, validated certificate or
approved remote-state backend, and no production GitHub environment/OIDC role
is configured. A real cloud plan was therefore **not run**, and no cloud
resource, billable or otherwise, was created. Local Terraform
format/validation/mock tests are not a real-account plan. See [AWS deployment
